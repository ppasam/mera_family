# mera_family

[![CI](https://github.com/ppasam/mera_family/actions/workflows/ci.yml/badge.svg)](https://github.com/ppasam/mera_family/actions/workflows/ci.yml)

Модуль, который берёт список желаний клиента, находит перечисленные товары на
маркетплейсах, показывает 1–3 лучших варианта по цене и сроку доставки и после
подтверждения клиента кладёт выбранный в корзину.

## Статус

Работает сценарий «поиск → подборка → корзина» для ozon.ru. Первый отработанный
запрос — «омега 3 solgar».

## Как это устроено

```
wishlist → фильтр → поиск (адаптер) → обогащение → ранжирование → показ → выбор клиента → корзина → журнал
```

Ядро не знает про конкретный маркетплейс: адаптер приводит данные площадки к
общим моделям `Offer` / `Seller` / `Delivery`. Чтобы добавить Wildberries или
Яндекс.Маркет, нужна только новая реализация протокола `MarketplaceAdapter` —
ранжирование, показ и журнал остаются прежними.

### Почему не парсинг HTML

Витрина Ozon отдаёт данные через внутренний API `composer-api` в виде
типизированных блоков (`priceV2`, `textDS`, `labelListV2`). Модуль читает
именно их, а не разметку: смена вёрстки или CSS-классов ничего не ломает.

Запрос к этому API выполняется **изнутри уже открытой страницы ozon.ru** — через
`fetch` в контексте самой витрины. Он уходит same-origin, с настоящими куками и
заголовками браузера, и выглядит для площадки как обычная работа её же SPA.

### Работа от имени клиента

Модуль не подделывает клиента, а работает в его настоящей сессии:

- собственный постоянный профиль Chrome, в который клиент **один раз входит
  руками** (`wishlist login`); пароль и код из СМС модуль не видит и не хранит;
- темп задан в `Pace` и намеренно медленный: паузы между действиями, прокрутка
  страницы, лимит запросов за сессию;
- **капча не обходится**: увидели проверку — остановились и отдали управление
  человеку;
- **оплату модуль не подтверждает** ни при каких условиях: кнопку «Оплатить»
  нажимает клиент, сбой скрипта не может стоить денег. Сейчас сценарий
  останавливается ещё раньше — на корзине; шага «оформить заказ» в коде пока
  нет.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -e .
cp .env.example .env          # при необходимости поправить пути
cp config/wishlist.example.yaml config/wishlist.yaml
```

Нужен установленный Chrome — модуль запускает системный браузер (`channel="chrome"`).

## Использование

```bash
wishlist login                     # разовый вход клиента в аккаунт
wishlist search "омега 3 solgar"   # подборка без покупки
wishlist buy "омега 3 solgar"      # подборка → выбор клиента → корзина
wishlist run --buy                 # то же по всему списку желаний
```

Список желаний — `config/wishlist.yaml`. Короткая форма пункта: строка запроса.
Развёрнутая: бренд, синонимы, обязательные и запрещённые слова в названии,
потолок цены, количество. Пример — `config/wishlist.example.yaml`.

`must_include` сравнивает написание буквально: `solgar` отсечёт товары,
подписанные кириллицей как «Солгар». Это инструмент точной настройки — если
нужны оба написания, укажите `must_include: []` и полагайтесь на `brand`.

## Разработка

```bash
PYTHONPATH=src .venv/bin/python -m pytest tests/ -q
```

Тесты не ходят в сеть: они работают на фикстуре реального ответа витрины
(`tests/fixtures/`). Снять свежую фикстуру — `scripts/probe_composer.py`.

Перед коммитом новой фикстуры её обязательно нужно очистить: ответ витрины
содержит трекинговые токены сессии браузера, которым фикстуру снимали.

```bash
.venv/bin/python scripts/sanitize_fixture.py tests/fixtures/<файл>.json
.venv/bin/python scripts/check_fixtures.py    # то же делает CI на каждый коммит
```

### CI

`.github/workflows/ci.yml` на каждый push и pull request прогоняет три задачи:

| Задача | Что проверяет |
|---|---|
| Линтер и формат | `ruff check` и `ruff format --check` |
| Фикстуры без следов сессии | `scripts/check_fixtures.py` — что в фикстурах не осталось токенов |
| Тесты | `pytest` на Python 3.12 и 3.13 |

Браузер в CI не устанавливается: тесты работают на сохранённом ответе витрины и
в сеть не ходят. Живые прогоны делаются вручную на машине клиента.

### Релиз

Деплоя у модуля нет — он запускается на машине клиента вместе с его браузером.
Поэтому релиз означает собранный пакет, приложенный к релизу на GitHub:

```bash
# поднять version в pyproject.toml, затем
git tag v0.1.0 && git push origin v0.1.0
```

`.github/workflows/release.yml` прогонит тесты и проверку фикстур, соберёт wheel
и sdist, сверит версию в `pyproject.toml` с именем тега и создаст релиз.

Вспомогательные скрипты:

| Скрипт | Зачем |
|---|---|
| `scripts/probe_composer.py` | запросить `composer-api` и сохранить ответ в фикстуры |
| `scripts/recon_ozon.py` | перехватить запросы витрины при обычной навигации |
| `scripts/diag_ozon.py` | посмотреть, что витрина отдаёт браузеру модуля |

## Ограничения и риски

- Пользовательское соглашение Ozon не приветствует автоматизированный доступ.
  Модуль рассчитан на личный аккаунт клиента и небольшой список желаний;
  темп и лимиты в `Pace` занижать не следует.
- Витринную цену нельзя получить официальным API: Ozon убрал `marketing_price`
  из Seller API. Поэтому цена берётся только с витрины.
- Структура ответов `composer-api` не документирована и может измениться. Признак
  поломки — пустая выдача при живой странице; лечится обновлением фикстуры.

## Демонстрационная страница

`demo/` — наглядный прототип интерфейса покупателя: поле ввода товара из списка
желаний, выбор площадки, карточки найденных предложений и выбор варианта.

Страница работает на **настоящих данных**: фикстура ответа витрины проходит через
тот же парсер и тот же ранжировщик, что и живой поиск. Изменится логика отбора —
изменится и демо.

```bash
.venv/bin/python scripts/build_demo.py   # собирает demo/index.html
```

Сборка вшивает данные и картинки товаров в страницу, поэтому `demo/index.html`
открывается двойным кликом — без сети и без обращений к маркетплейсу. Покупка в
демо не выполняется: по кнопке показывается, что произошло бы при настоящем
запуске.

Готовый `demo/index.html` и `demo/offers.json` в репозиторий не коммитятся —
они собираются из `demo/template.html` и фикстуры.
